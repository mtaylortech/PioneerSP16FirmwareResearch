# Accepted initial numerical specification and host limits

The owner selected these choices in this chat on October 11, 2026 after requesting internet research. WAV signed PCM16/24, 44,100/48,000/96,000 Hz, mono/stereo, audible preview required. The owner adopted the recommended −1 dBFS sample-peak ceiling, nearest rounding, no added dither, exact silence unchanged, all nonzero audio normalized without a gain cap. Maximum file size: 50 megabytes, implemented as **50,000,000 bytes including headers/metadata**. No separate duration limit was selected.

This is not a single industry-mandated setting. [Audacity's Normalize documentation](https://manual.audacityteam.org/man/normalize.html) defaults to −1 dB and linked stereo; [Adobe's Normalize documentation](https://helpx.adobe.com/ph_en/audition/desktop/effects-reference/amplitude-compression-effects.html) describes configurable percentage/dB targets including 0 dBFS. The selected tools therefore support different targets. Their inspected pages do not specify a common near-silence threshold or maximum gain cap. The no-threshold/no-cap policy is an owner-adopted product choice, not a discovered standard.

[Audacity's dither documentation](https://manual.audacityteam.org/man/dither.html) explains quantization error and the noise tradeoff when processing into integer formats. Deterministic nearest rounding with no dither was recommended for this project's exact-zero requirement and adopted by the owner. It does not claim all industry tools use this rule or that quantization is inaudible. Research consulted October 11; source URLs and claim boundaries are retained here. No copyrighted manual was reproduced in full from the web.

For every interleaved decoded integer sample `x`, across the **entire recording and all channels**, calculate `P = max(abs(x))`. Let `S = 2^(bits−1)` and `C = floor(S * 10^(−1/20))`. The implementation uses an 80-digit Decimal coefficient represented as an exact Fraction; targets are independently pinned at **29204 for PCM16**, **7476354 for PCM24**. Both are below the selected nominal ceiling by less than one sample unit. If `P=0`, copy audio bytes unchanged. Otherwise apply the single exact rational gain `G=C/P`; nearest rounding with ties to even gives output `y`. Every zero remains zero; `abs(y−G*x) ≤ 0.5` sample units. The peak sample lands exactly at `C`. No clamping, compression, DC correction, trimming, channel rebalance, rate conversion, dither or bit-depth conversion occurs. Uniform stereo balance holds before rounding; the stated quantization error is the finite representation limit.

Signed extrema are decoded into host arbitrary-precision integers, so `abs(-32768)` and `abs(-8388608)` cannot overflow. Exact 0 dBFS development examples use a symmetric representable ceiling `min(floor(S*ceiling), S−1)`; they do not change the adopted −1 dBFS profile. Very low nonzero recordings can receive very large gain, which raises existing noise. Preview must present that processed audio and the gain before Keep. This is sample-peak qualification; no DAC/inter-sample/true-peak, mixer, effects or hardware clipping qualification is claimed.

`profile.owner_profile()` contains the accepted envelope. The parameterized core also has explicit development-only alternatives (32-bit PCM, different ceilings/rounding, near-silence refusal/unchanged and amplification cap). Those cases are labelled `dev-*`/examples in controls and are not product support. Block size is an implementation parameter; the suite proves its tested values do not affect output.

Preservation policy of this host artifact: complete little-endian RIFF/WAVE; exactly one 16-byte PCM `fmt ` and one `data` chunk; no tail bytes or partial frames. Preserve every permitted nonaudio chunk, its order/header/pad, and data padding byte-for-byte. Permitted ancillary chunks: `JUNK`, `PAD `, `LIST` of type `INFO`, `cue `, `smpl`. These are treated as opaque preserved geometry/text chunks; this core does not certify their internal schema or accept every WAV metadata standard. Refuse `PEAK`, `bext`, `fact`, hashes, unrecognized chunks, non-INFO lists, extensible/float/8-bit/RF64/RIFX/AIFF and duplicate audio/format chunks. Amplitude-dependent statistics/checksums may become invalid and are not silently retained/dropped. Broad metadata and adjunct support is a remaining product prerequisite.

Input bytes/mode/mtime are checked on fixtures. Output is a new exclusive 0600 disposable file inside the owned experiment; **this does not implement original-file attribute preservation**. Hard links/symlinks/outputs outside the owned fixture directory are refused. Input mutation detection requires caller-controlled fixtures and is not an adversarial alias/quiescence protocol. Output writes loop on positive short results; any error or close failure propagates without a complete receipt. Partial output remains disposable diagnosis, never a qualified candidate. No fsync/rename/backup/Keep transaction exists here.

Independent oracle: stdlib WAV geometry/PCM16/32 decoding and a separate PCM24 byte-arithmetic decoder; expected gain comes from predeclared fixture samples/targets, not the production receipt. Integer quotient/remainder implements expected rounding independently of production Fraction rounding. Full decoded sequence, peaks, quantization bounds, zeros, output completeness, geometry and permitted metadata are checked. Maximum-size zero fixtures use bounded independent WAV reads and whole-file hashes. Deliberate wrong processing outputs must fail this oracle.
