# TORAIZ SP-16 MIDI implementation

Scope: published documentation through firmware 1.60, **cross-confirmed** against
the firmware's own classes and a real project file. No instrument testing.

This chart was built from Pioneer's documentation (the original Operating
Instructions have no MIDI appendix; the missing information is in the firmware
1.60 addendum). It is then corroborated by the reverse-engineering in this repo:
the MIDI classes recovered in [architecture.md](architecture.md)
(`MidiSender`, `MidiClockInterpreter`, `MidiCc1/2ViewController`) and the
`MidiSettingData` / `MidiCc1Data` / `MidiNoteData` nodes decoded from a real
project in [project-format.md](project-format.md). Where the manual and the
firmware data agree, it is noted.

## Sources and citation convention

- **A:** Pioneer DJ, *Firmware Version 1.60 Operating Instructions Addendum*,
  89 pages. [B&H mirror](https://www.bhphotovideo.com/lit_files/775211.pdf),
  [Manuals+ mirror](https://manuals.plus/m/4ce0d558fd6bf410bf58b00f047ace713f1a1d1f1280f77f95a58792a755d3ff.pdf).
  Direct Pioneer access returned HTTP 403; the mirrored text was inspected.
  **A page numbers** are the printed addendum pages.
- **G:** [MIDI Guide SP-16 CC reference](https://midi.guide/d/pioneer-dj/toraiz-sp-16/),
  35 parameters; cross-checked against A, pp. 87-88.
- **M:** Original *Operating Instructions*, DRI1377-B, 47 pages (not
  redistributed here). MIDI connectors pp. 5-6; synchronization pp. 3, 41-42.

**SEND** = generated by the SP-16; **RECEIVE** = interpreted by the SP-16.
**Documented** = stated in A. **Inferred** = a reasonable reading A does not
state at message level.

| Program Change | Documented | Not specified | Per-scene values; scene change can change external device program. | A 38-41 |

Incoming notes are restricted to SAMPLE tracks, incoming CC to SAMPLE/THRU
tracks (A 45-48). No support/non-support verdict should be inferred from an
omission.

## Channels, ports, firmware differences

- **Receive-channel mapping (1.60):** each track selects CH.1-16 or OFF; multiple
  tracks may share a channel (supersedes the 1.20 one-track-per-channel rule). A 11.
- **Default mapping:** track n → channel n. A 46, 48.
- **Inputs (1.60):** channel messages received from both DIN MIDI IN and USB-B;
  the old MIDI I/F SELECT was removed. A 13.
- **Sync source (1.60):** INTERNAL, PRO DJ LINK, DIN MIDI, or USB MIDI. A 13.
- **DIN output modes (1.60):** OUT; OUT+MIDI IN; OUT+USB IN; THRU (MIDI IN);
  THRU (USB IN). **USB output modes:** OUT or OUT+MIDI IN. A 12.
- MIDI IN/OUT were 1.20 additions; Bank Select/Program Change 1.30; routing/
  channel changes 1.60. Do not project FX2 receive assignments onto older firmware.

## Firmware cross-confirmation (from this repo's reverse engineering)

Decoded directly from a real project's `MidiTrackData` node (see
[project-format.md](project-format.md)), which independently corroborates the
documentation above:

- **`MidiSettingData` → `Input` / `Output`** each carry `bUseClock`,
  `bUseStartStop`, `bUseNoteCC`, `bUseSongPosition` (bool) and `channelNo`
  (array) — exactly the independent IN/OUT transport-message enables A describes.
- **`MidiCc1Data`** stores the outgoing CC1 module: `pitchBend`/`afterTouch` as
  fixed params 1-2, then programmable params 3-6 with default CC numbers
  observed as **7 (Volume), 1 (Mod), 2 (Breath), 10 (Pan)**, each with a value
  and an `Active` flag.
- **`MidiCc2Data`** stores the outgoing CC2 module: params 1-6 with default CC
  numbers observed as **71-76** (sound controllers), each with value + `Active`.
- **`MidiOtherData`**: `bankselmsb`, `banksellsb`, `programchange` — the per-scene
  Bank Select / Program Change values A documents.
- **`MidiNoteData`**: `note1`-`note4`, `velocity`, `length` — the "up to four
  notes per trigger", velocity and length fields A documents for MIDI-track output.

## Remaining gaps

The located appendix is primarily a receive-function list. SysEx, Active Sensing,
pressure subtype, detailed Note Off rules, transport edge behavior, CC value
scaling, and incoming Program Change remain undocumented. The G "CCs & NRPNs"
title does not establish an SP-16 NRPN implementation.
