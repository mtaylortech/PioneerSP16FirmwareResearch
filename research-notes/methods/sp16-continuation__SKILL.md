# SP16 continuation

Start with the current request, applicable [AGENTS.md] `../../../AGENTS.md` (evidence not published), [README] `../../../README.md` (evidence not published) and latest relevant handoff. These govern workspace boundaries and authorization; this skill expands neither. Reconcile newer completed evidence with older proposed next actions. Read only what carries the selected question forward; avoid reconstructing the chronology. The [takeover example](../history/handoffs/README.md) illustrates successor structure; the [completed investigation] `../../../experiments/normalization-pending-editor-load-settlement-20261010-step09f/HANDOFF.md` (evidence not published) illustrates how a later result supersedes an older next action. Keep current findings in maintained handoffs.

Carry the actual feature contract, established results and confidence limits, retained failures, source/environment distinctions, unresolved dependency and one next consequential question. Anchor claims to evidence paths rather than chat memory or unsupported summaries. Separate static source joins, adapted fixtures, original guest observations and physical-unit behavior. Do not relabel a completed local phase as an open blocker or convert an unbound candidate edge into a stock defect.

When a continuation artifact is requested, include objective, starting evidence, permitted actions and boundaries, carried authorization/budget/attempt limits, proposed output location, acceptance or stop condition, and remaining owner decisions. Preserve existing authority without redundant permission exchanges. Distinguish preparation-only work from execution actually requested. Never invent authorization, renew spent allowances or silently shorten an agreed observation. A brief status question can be answered directly without saving a handoff.

Carry necessary local dependencies and preservation limits. Verify specific referenced files or preservation claims when required by the request; do not turn every continuation into a backup or Git audit. Local commits, native databases, off-device backup and automatic AI memory are distinct claims. A checkout alone may omit original firmware, native projects and raw receipts; point to the applicable dependency records instead of copying an inventory.

Respect the active workspace role. In an instructions-only review workspace, prepare the main-project prompt in the permitted review location. Preparing a prompt or handoff does not authorize sending it, creating/archiving chats or executing its proposed task. Continuing already authorized work does not require a new chat.

Reuse an existing handoff when a narrow update suffices; preserve completed evidence and avoid duplicate state, ledger and changelog reports. Date newly prepared artifacts in America/Chicago. Keep volatile next actions and owner decisions out of this skill.
