# Project-save trace — October 10, 2026

Question: when can the changed original 1.50 `PlaybackData.audioSourceUrl` reach persistent project storage, and which destinations are involved?

Result: explicit Project Save reaches recursive serialization of the project model containing PlaybackData. A successful save can conditionally update a separate resume file. This closes the explicit-save route statically; automatic activation after SAVE & REPLACE, durable completion and reader refresh remain unresolved. No firmware or guest was executed.

## Verification, failures and limits

Independent ELF-segment byte checking passed for 29 accepted exports and 13,668 instruction records, with 58 focused checks. All 13 owned process groups (ten analysis batches and three controls) were absent; no owned Ghidra project lock remained. TERM and forced-KILL supervision controls passed. The zero-exit required-failure fixture was retained as a failure indication; its original control only checks the marker, so it is not a comprehensive evidence acceptance validator. Other negative checks are narrow original-word/source comparisons, not a complete fault-injection suite.

Four guessed interior function starts produced misbounded discovery exports (`0x33e8c0`, `0x33e968`, `0x337038`, `0x33704c`). Those artifacts remain preserved, are explicitly excluded from accepted byte-export results, and were replaced by confirmed entry exports. Discovery string/data scans and inferred C alone are not proof. A final verifier retry used the system Python and failed before checks because `elftools` was absent; [stderr] `logs/verification-final.stderr.txt` (evidence not published) is retained. Repeating with the installed emulation Python passed; [stdout] `logs/verification-repaired.stdout.txt` (evidence not published) and [stderr] `logs/verification-repaired.stderr.txt` (evidence not published) are saved. No guest completion is claimed. Originals and prior helper identity remained unchanged.

This establishes explicit Project Save, not an exhaustive write-effects or recovery map. Optional audio copying, archival paths, external synchronization and automatic save policy remain open. No real project was written, no restart/reload was tested, and Normalize → Keep/Discard remains unimplemented and unproved.
