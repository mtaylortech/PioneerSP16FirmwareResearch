# SP-16 1.60 startup: static findings

**The original initializer constructs application services and the UI, then returns to a framework wrapper. That wrapper makes a separate 0/1 decision; main enters X11/internal-message dispatch only on its nonzero result. A bounded status/mode poll inside initialization may exhaust its counter and still continue normally.** Its completion therefore does not establish that all devices, background work, or audio processing are ready.

This is analysis of original bytes, with supported interpretations explicitly identified below. All `.inferred.c` files are decompiler pseudocode, not recovered source or verified execution. The prior [completed lifecycle run] `experiments/startup-lifecycle-live-20261009-165946/HANDOFF.md` (evidence not published) independently records actual initializer/wrapper returns and dispatch at 262.072s, followed by async acceptance at 269.430s. Those are historical runtime receipts; this task ran only static tooling and sent no input.

## Completion decision and dispatch

The concrete preinitialization slot `+0x10` points to `0x56e8ec`, exactly `mov r0,#1; bx lr`. Thus this application's usual path bypasses the wrapper's alternate early-rejection check. After the initializer returns, the wrapper destroys its context and clears application byte `+8` at `0x698558`. It ensures a message manager exists and examines **manager byte `+4`** at `0x698568`. Nonzero yields return 0; zero optionally registers application `+0xc` using sorted insertion `0x696e68`, then returns 1. It **does not test the initializer's r0 as a success result**. Initializer `void` and wrapper `uint` prototypes are analyst conventions supported by this register use, not recovered source signatures. Exceptions and nonreturning callees can bypass the normal chain. [Wrapper pseudocode] `ghidra/exports/refine/0069850c.inferred.c` (evidence not published)

At `0x69afc0`, the message loop tests manager byte `+5` (`0x69b04c`) and returns when set. It alternates X11 servicing (`XPending` at `0x69affc`, `XNextEvent` at `0x69b010`, plus a second path) with a mutex-protected internal queue. Internal messages invoke virtual slot **`+8`** at `0x69b1bc` or `0x69b348`; X events go through indirect globals `0xf6e6a8/0xf6e6ac`. When neither source is ready, `select` at **`0x69b4e0`** waits on the socketpair read descriptor and the X connection (`XConnectionNumber` at `0x69b478`). Bootstrap `0x697fc0` supplies socketpair/X11 setup, `DISPLAY`/`:0.0`, and an auxiliary window. **Interpretation:** JUCE-style X11 and asynchronous message dispatch; exact callbacks and flag writers remain incompletely resolved. [Dispatch instructions] `ghidra/exports/refine/0069afc0.asm.txt` (evidence not published), [imports/call references] `ghidra/exports/refine/0069afc0.json` (evidence not published)
