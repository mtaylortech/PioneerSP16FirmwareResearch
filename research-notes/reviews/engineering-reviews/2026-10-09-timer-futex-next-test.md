# Next meaningful test: the repaint timer's finite futex wait

Reviewed October 9, 2026, America/Chicago. This review inspected original code and retained experiment evidence; it launched no guest and changed no runtime. A newer cooperative-select experiment finished during the review, so its final records supersede the README's earlier Expose-only frontier for this decision.

**Recommendation:** test a working-copy correction that honors the original `Juce Timer` thread's finite relative `FUTEX_WAIT` deadline. First verify the deferred syscall contract without firmware, then use one new 600-second observation to see whether the original repaint timer consumes pending dirty work and reaches painting. This is a concrete emulator contract defect on the observed rendering path. Another observation of Expose delivery or a duration-only repeat would leave that defect in place.

**Evidence supporting the choice.** The completed [Expose-chain handoff] `../experiments/expose-chain-20261008/HANDOFF.md` (evidence not published) already proved context lookup, per-window dispatch, original virtual target `0x7fd0d0`, and matched returns. The newer [cooperative-select raw trace] `../experiments/cooperative-select-20261008/run-1/supervision/guest.stdout.txt` (evidence not published) goes further:

- At probe elapsed **263.049–263.050s**, the selected Expose has rectangle `(1,1,800,480)` inside object dimensions `802×482`. Clipping preserves that rectangle. The manager is `0x1860e300`, its timer state at `+8` is **10**, and its dirty-region collection at `+0x20` already contains `(0,0,802,482)`. That larger region remains after the matched `0x4ffc80` return. The count staying at one is consistent with retaining covering work; it is not evidence of rejection. This frame takes the already-scheduled branch, so absence of a fresh `0x69bf5c` scheduling call is expected.
- At **263.120s**, original thread **2026**, named **`Juce Timer`** by `prctl`, issues private relative `FUTEX_WAIT` (`op=128`) on **`0x17ce07c`**, requesting **90,506,129 ns**. The actual installed handler returns a placeholder zero and defers to a wait that does not enforce the supplied timeout. At the **598.182s** sparse sample, that exact thread/address remains in `deferred_begin`: at least **335.061 seconds** waiting for a requested **0.090506 seconds**. The native final retains the same pending state. An earlier wait on `0x17ce02c` *did* complete after an attributed wake by main; the observer can distinguish wake completion from an outstanding wait.
- The [installed syscall dispatcher] `../experiments/emulation-20261007/tools/venv/lib/python3.10/site-packages/qiling/os/posix/syscall/futex.py` (evidence not published) discards the timeout argument for `FUTEX_WAIT`. Its [futex manager] `../experiments/emulation-20261007/tools/venv/lib/python3.10/site-packages/qiling/os/linux/futex.py` (evidence not published) calls `event.wait()` without a bound. The newer experiment's [focused control] `../experiments/cooperative-select-20261008/controls.json` (evidence not published) already exercises this ignored-timeout/deferred-wake behavior; this review did not repeat it.

[Extracted receipts, exact source-prefix identity and final records] `../experiments/ui-timer-review-20261009/trace-snapshot.json` (evidence not published), [static boundaries] `../experiments/ui-timer-review-20261009/static-boundaries.json` (evidence not published), and [analysis command/code identities] `../experiments/ui-timer-review-20261009/execution.json` (evidence not published) retain the evidence used here. Times above are probe elapsed, not guest-creation elapsed.

**Result and limits.** Cooperative select permits other greenlets to run while main waits and this guest writes a native `bounded_stop` final at **600.726s**; the guest process exits zero with no owned guest signal. [Owned closure] `../experiments/cooperative-select-20261008/run-1/attempt-supervision.json` (evidence not published), [endpoint/process postflight] `../experiments/cooperative-select-20261008/run-1/endpoint-postflight-initial.json` (evidence not published), and [display-helper reaping] `../experiments/cooperative-select-20261008/run-1/display-observer-closure.json` (evidence not published) pass. This is a successful bounded observation, not original application completion. Resource returns remain **1,314**, neither painting site fires, and both exact **800×480** drawable captures have zero nonblack pixels. Two samples do not establish continuously black output. The older missing native finals remain real historical failures.

Confidence is high that the installed timeout contract is broken and this live timer is held beyond its requested deadline. Confidence is moderate that correcting it advances rendering: the timer consumer/callback has not yet been matched live. Other incomplete futex operations, clock semantics and devices can still block later progress. The current verifier's `relevant_waits` filter includes `TimerThread` but omits the actual name `Juce Timer`; use the raw receipts and final `waits.thread_states`, and correct that selection in the next working copy. The previously cited UI-blocker review is absent; no claim here depends on it.

**Smallest experiment and decisions.** Keep cooperative select, the established writable seed, statfs/ioctl guards, original app/libraries, cooperative-main condition, null audio and display fixture. Initially limit the functional intervention to finite relative `FUTEX_WAIT` from the observed original `Juce Timer` wrapper; identify the thread and loaded wrapper at runtime rather than hard-coding thread or heap addresses. Leave untimed waits and other operations delegated. Keep clock and pacing conditions unchanged so the result answers the timer-wait question.

In a fresh working copy, validate the real installed dispatcher/scheduler with fake guest memory/context: value mismatch returns `-EAGAIN`; zero and finite expired waits return `-ETIMEDOUT`; wake before expiry returns zero; invalid timespec returns `-EINVAL`. Verify timeout/wake races remove exactly one waiter, later wakes do not count expired entries, and completion writes only the waiting thread's saved `r0` after context save. Test cancellation/cleanup and another runnable thread. An unconditional early success return would not test the required contract.
2. Plan **one 600-second guest within a fresh 20-minute session**. The completed cooperative-select allowance is consumed; this review adds no attempts. Retain unused owned endpoints/private credentials, host-execution/network guards, independent duration-derived TERM/KILL/reap at **+605/+608/+610s**, ownership-aware shutdown and postflight. Reuse unchanged supervision and fixture controls; control only the new wait completion and hook contracts.

Use sparse, byte-validated receipts for the selected timer wait's entry/completion and original `pthread_cond_timedwait` caller return, timer worker `0x69f9bc` and countdown processing, then the selected manager's original callback candidate **`0x806840`** and painting path **`0x805e38`**. Match the live manager pointer/vtable and thread/SP; static addresses alone are not executed milestones. Retain both `XPutImage` sites `0x783bb8 / 0x806640` and exact drawable captures after any paint plus near the bound. Retire the completed Expose-chain/rectangle observations once attribution is established.

If the timer resumes with the proper timeout, decrements pending work and reaches the manager callback, follow the first missing paint/transfer boundary within that same observation. If it resumes but no countdown or callback follows, inspect the recorded clock/counter or message-queue gate before selecting another correction. If pixels change, inspect original content and input response before claiming usable UI. Stop on a real fault, byte/frame mismatch, guard breach or the finite deadline. Report the result as a causal rendering experiment; there is no matched performance comparison here.
