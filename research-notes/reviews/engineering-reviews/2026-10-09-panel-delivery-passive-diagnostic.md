## Delivery finding and confidence

No `add_fs_mapper` targets `/dev/subucom_spi0.1`; no device object or record producer is selected by this probe. The saved rootfs's panel path is absent, with only `mtab` in `/dev`. `guarded_read` special-cases owned display/local IPC descriptors; other reads use installed `ql_syscall_read`. `QlFsMapper` otherwise opens the rootfs-resolved host path. Installed `__do_open` catches `QlSyscallError` and returns -1. Ordinary read preserves short reads and EOF; it does not assemble or pad a 128-byte record. The epoll fixture polls the registered object's host `fileno()` using `select`, copies a 16-byte ARM event preserving the fd at +8, and rejects an out-of-range fd with -9. A future mapped object therefore needs readiness and read behavior as well as a path mapping. A regular file is not an established record transport.

The source finding is high confidence for the identified installed condition. The saved original guest logs panel open at 1.997701s and epoll creation at 2.017402s, without a successful registration event. It does **not** log actual open or ADD return operands. Synthetic -1/-9 controls exercise extracted function bodies with explicit fake state; they are not live original-libc results. Application-side libc return normalization is a separate boundary, so the prepared observer records actual signed/raw returns rather than assuming raw syscall values. Original `0x56d770/774` tests for -1; the preserved failure branch logs, closes epoll and leaves the worker. That branch was statically inspected, not claimed to have executed in the saved guest.
